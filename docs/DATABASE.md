# Дерекқор: құрылымы, толтыру, резервтік көшірме

Колледждің IT маманына арналған нұсқаулық. Портал бір PostgreSQL 16 дерекқорында жұмыс істейді; ол колледж серверінде Docker ішінде тұрады (`docker-compose.yml`).

## 1. Қайда тұрады

| Не | Қайда | Ескерту |
|---|---|---|
| Дерекқор (PostgreSQL 16) | `db` контейнері, `pgdata` Docker томы | 5432 порты сыртқа ашылмайды: оған тек `app` пен `backup` қосылады |
| Жүктелген файлдар (медициналық анықтамалар) | `uploads` Docker томы | `src/lib/storage.ts` |
| Резервтік көшірмелер | серверде `./backups/` қалтасы | `backup` контейнері күн сайын жазады; серверден тыс жерге де көшіру керек (5-бөлім) |
| Схема | `prisma/schema.prisma` + `prisma/migrations/` | дерекқор құрылымының жалғыз дерек көзі |

Барлық жеке деректер (ЖСН, бағалар, денсаулық туралы анықтамалар) колледждің өз серверінде, Қазақстан аумағында сақталады. Бұл «Дербес деректер және оларды қорғау туралы» заңның деректерді ел ішінде сақтау талабына сай келеді; бұлтқа көшірерде осыны ескеріңіз.

## 2. Кестелер картасы

| Бөлім | Кестелер |
|---|---|
| Адамдар | `User` (рөл: STUDENT, TEACHER, VICE_PRINCIPAL, DIRECTOR, PARENT, ADMIN; `active`), `ParentLink` (ата-ана ↔ бала) |
| Оқу процесі | `Group`, `Course`, `Room`, `Schedule` (апталық кесте), `LessonRecord` (тақырып, үй жұмысы), `Grade` (100 балл), `Attendance`, `Syllabus` |
| Өтінімдер | `MedicalCertificate`, `Booking` |
| Мазмұн | `Announcement`, `Rule` |
| Куратор | `StudentProfile`, `Guardian`, `ContactLog`, `CuratorTask`, `ClassEvent`, `Achievement`, `BookRead`, `TestResult`, `Reflection` |
| Жүйе | `AuditLog` (админ панельдегі әр өзгеріс), `_prisma_migrations` (қолданылған миграциялар) |

Негізгі ережелер:
- Адам ешқашан өшірілмейді деп есептеңіз: бітірген студент пен кеткен мұғалім `active = false` болады. Олардың бағалары мен журналдағы жазбалары сақталады, бірақ жүйеге кіре алмайды.
- Студенттің ЖСН-і мен қызметкердің поштасы бірегей (`@unique`): импорт адамды солар бойынша табады.
- Студенттері бар топты, бағасы бар пәнді, сабағы бар кабинетті өшіру мүмкін емес: админ панель тоқтатады.

## 3. Алғаш толтыру (продакшн)

Демо деректер (`npm run db:seed`) продакшнда **қолданылмайды**: ол бар деректерді өшіреді.

1. `docker compose up -d --build`: дерекқор құрылады, миграциялар өзі қолданылады.
2. Алғашқы әкімші: `docker compose exec app npm run admin:create -- it@jihc.edu.kz "Аты-жөні"`. Сосын ол Google (@jihc.edu.kz) арқылы кіреді.
3. Админ панель → **Кабинеттер**, **Пәндер**: тізімді енгізу (Excel-ге шығарып, тексеру оңай).
4. Админ панель → **Excel-ден импорт**: EduPage-тен студенттер тізімін (Аты-жөні, ЖСН, Топ) көшіріп қою; топтар өзі құрылады. Мұғалімдерді (Аты-жөні, Пошта, Рөлі = Мұғалім) дәл солай.
5. **Топтар**: Smart Nation атауы мен кураторды қою. Завуч, директор рөлдерін **Пайдаланушылар** бетінде беру.
6. **Кесте генераторы** (завуч): апталық кесте.
7. **Ата-ана PIN-кодтары** (завуч): әр топқа PIN парақтарын басып шығару.

Импортты қайталауға болады: бар адамдар жаңартылады, жаңалары қосылады, ешкім екі рет жазылмайды.

## 4. Схеманы өзгерту (жаңа нұсқа шыққанда)

- Әзірлеуші `prisma/schema.prisma`-ны өзгертіп, `npx prisma migrate dev --name <атауы>` арқылы жаңа миграция жасайды және оны репозиторийге қосады.
- Серверде: алдымен қолмен резервтік көшірме (6-бөлім), сосын `git pull && docker compose up -d --build`. Контейнер іске қосылғанда `prisma migrate deploy` жаңа миграцияларды өзі қолданады.
- Дерекқорды қолмен (psql арқылы) өзгертпеңіз: келесі миграция сәйкессіздік табады.

## 5. Резервтік көшірме

`backup` сервисі (`scripts/backup.sh`) іске қосылғанда бір рет, сосын күн сайын 02:00-де (Алматы):
- `backups/db/jihc-YYYY-MM-DD_HHMM.dump`: бүкіл дерекқор (`pg_dump -Fc`);
- `backups/uploads/uploads-YYYY-MM-DD.tar.gz`: анықтама файлдары;
- 30 күннен ескі көшірмелерді өшіреді (`KEEP_DAYS`).

Тексеру: `docker compose logs --tail 20 backup` (әр түнде `backup ok` жолы шығуы керек).

**Серверден тыс көшірме міндетті** (сервердің дискі істен шықса, көшірмелер де жоғалады). Мысалы, басқа компьютерге күн сайын:

```bash
# басқа машинаның crontab-ы: 03:00-де серверден тартып алу
0 3 * * * rsync -a --delete jihc-server:/opt/jihc-portal/backups/ /mnt/backup-disk/jihc/
```

Ең болмағанда аптасына бір рет сыртқы дискіге көшіріңіз. Айына бір рет қалпына келтіруді тексеріңіз (6-бөлім, бос дерекқорға).

## 6. Қалпына келтіру

```bash
# Қолмен көшірме (жаңарту алдында)
docker compose exec backup sh -c 'pg_dump -Fc -f /backups/db/manual-$(date +%F_%H%M).dump'

# Тексеру үшін бөлек дерекқорға қалпына келтіру (жұмыстағы деректерге тимейді)
docker compose exec db createdb -U jihc restore_test
docker compose exec -T db pg_restore -U jihc -d restore_test --no-owner < backups/db/jihc-2026-10-28_0200.dump
docker compose exec db psql -U jihc restore_test -c 'select count(*) from "User"'
docker compose exec db dropdb -U jihc restore_test

# Нақты қалпына келтіру: қосымшаны тоқтатып, дерекқорды көшірмемен ауыстыру
docker compose stop app
docker compose exec -T db pg_restore -U jihc -d jihc --clean --if-exists --no-owner < backups/db/jihc-2026-10-28_0200.dump
docker compose start app

# Анықтама файлдары
docker run --rm -v jihc-portal_uploads:/uploads -v "$PWD/backups/uploads:/b" alpine tar -xzf /b/uploads-2026-10-28.tar.gz -C /uploads
```

## 7. Қауіпсіздік

- `.env` ішіндегі `POSTGRES_PASSWORD` пен `NEXTAUTH_SECRET` ұзын әрі кездейсоқ болсын (`openssl rand -base64 32`). `.env` репозиторийге түспейді.
- Продакшнда `DEMO_LOGIN="false"`.
- Порталдың алдында HTTPS (nginx/Caddy). Дерекқор порты сыртқа ашылмайды.
- Админ панель тек `ADMIN` және `DIRECTOR` рөлдеріне ашық; әр өзгеріс `AuditLog`-та «кім, қашан, нені» түрінде сақталады.
- Сервер дискісін шифрлау (LUKS) және `backups/` қалтасына тек әкімшінің қол жеткізуі ұсынылады: онда ЖСН мен денсаулық деректері бар.

## 8. Көлемі және сервер

Шамамен 1 500 студент × 15 пән × 40 баға ≈ 900 мың баға жолы жылына, қатысумен бірге 2–3 млн жол: бұл PostgreSQL үшін аз (бірнеше жүз МБ). Сервер: 2 CPU, 4 ГБ RAM, 50 ГБ SSD жеткілікті; көшірмелер үшін бөлек диск жақсы. Дерекқордың ағымдағы көлемі админ панельдің басты бетінде көрінеді.
